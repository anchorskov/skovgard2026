## Campaign-to-Campaign Support

Jimmy Skovgard for Senate wants to help other candidates build practical campaign websites they can understand, maintain, and hand off cleanly.

This page outlines one workable model for getting a campaign site online quickly. It is not the only way to do it. We encourage every candidate, volunteer, and organizer to use their own imagination, adapt the process to their needs, and build something that fits their community.

We are not trying to force one template on everyone. We want to share a reliable starting point that can save time, reduce confusion, and help more local campaigns get moving.

If you want the fuller version of how Jimmy actually approached it, email <a href="mailto:jimmy@grassrootsmvt.org?subject=Website%20Help%20Please">jimmy@grassrootsmvt.org</a> and ask for help building a low-cost website.

## What This Support Can Help With

- Choosing a clear, affordable campaign domain
- Setting up hosting, DNS, and HTTPS
- Creating a GitHub repository the candidate can own
- Launching a simple site that can be updated locally
- Handing off the process so future volunteers can repeat it

## The Core Idea

We recommend a lightweight approach:

- Use a simple static site
- Keep the code in version control
- Publish through low-cost or free infrastructure
- Document the setup so the candidate keeps control

That said, this is only one option among many. Some campaigns may want a more custom design, a different hosting provider, a different editing workflow, or a different technology stack entirely. That is fine. The best system is the one the campaign can actually operate well.

## A Practical Starter Path

Here is one straightforward path a first-time campaign can follow:

### 1. Register a domain

Pick a domain that is short, easy to say, and easy to spell on signs, mailers, and social posts.

### 2. Set up hosting and DNS

Use a service that gives the campaign reliable hosting, SSL, and access control without creating unnecessary technical overhead.

### 3. Create a repo the candidate controls

The candidate should own the GitHub account or have direct control over it. That makes the website easier to transfer, preserve, and improve over time.

### 4. Start from a working template

A proven starter site can dramatically reduce setup time. Reuse the parts that help, remove the parts that do not, and replace all identity-specific content with the new candidate’s own voice, goals, and branding.

### 5. Document the workflow

If the campaign writes down what worked, what broke, and how it was fixed, the next volunteer or candidate starts from experience instead of from scratch.

## Use This as a Starting Point, Not a Box

This page is intentionally practical, but it should not limit anyone’s thinking.

If your campaign wants:

- A simpler one-page site
- A larger volunteer portal
- A donation-first landing page
- A candidate training hub
- A fully custom design

then build that. Campaigns work best when they reflect the people behind them. The strongest approach is often the one that matches the team’s actual skills, timeline, and energy.

## What We Recommend Regardless of Platform

Even if you choose a completely different setup, these principles still matter:

- The candidate should control the key accounts
- Access should be documented and shared intentionally
- Costs should stay predictable
- The site should be easy to update under pressure
- The process should be simple enough to hand off
