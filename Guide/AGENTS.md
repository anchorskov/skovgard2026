# Guide Sub-project — Agent Instructions

Voter guide admin and rubric scoring for the Wyoming 2026 primary. Lives at `guide.skovgard2026.org`, deployed as a **Cloudflare Pages** project. This file covers everything specific to `Guide/`. For campaign-wide rules see the root `AGENTS.md`.

---

## Quick reference

| Thing | Value |
|---|---|
| Pages project name | `skovgard-guide` |
| D1 binding | `WY_DB` → database `wy` (ID `4b4227f1-bf30-4fcf-8a08-6967b536a5ab`) |
| Deploy script | `./scripts/deploy_guide.sh` from repo root |
| Data-only redeploy | `SKIP_BUILD=1 ./scripts/deploy_guide.sh` |
| Candidate data | Shared with Candidates/ — same WY_DB instance |

---

## Key tables (guide_* schema)

| Table | Purpose |
|---|---|
| `guide_rubric_scores` | Per-candidate rubric category scores (10 categories, weighted) |
| `guide_endorsements` | Endorsements tied to candidates |
| `guide_corrections` | Factual correction records for guide pages |
| `guide_questionnaire_tokens` | Token-based candidate questionnaire URLs (no account needed) |
| `guide_questionnaire_responses` | Per-question candidate submissions |

All guide tables share WY_DB with `offices` and `candidates`. Do not confuse with the `ballot_sources` D1 used by the main campaign Worker.

## D1 migrations

Guide migrations live in `Guide/db/migrations/` (numbered 0001–0004). These are the same SQL as `Candidates/db/migrations/0012–0015` — both directories target the same `wy` database.

**Run from the `Guide/` directory against WY_DB:**

```bash
cd Guide
npx wrangler d1 migrations apply WY_DB --remote
```

Or run a specific file directly:
```bash
npx wrangler d1 execute WY_DB --remote --file=db/migrations/0001_guide_rubric.sql
```

Never run the same migration twice — `CREATE TABLE IF NOT EXISTS` is safe, but index creation and `ALTER TABLE` statements are not always idempotent.

## Deploy rules

- **Always use `./scripts/deploy_guide.sh`** from the repo root.
- This deploys to Cloudflare **Pages** (not a Worker). The script runs `wrangler pages deploy`.
- Do NOT run `npx wrangler pages deploy` directly — the script validates the project name and guards against `[env.production]` misrouting.
- Do NOT mix this project with `skovgard-candidates` or `skovgard2026-api`.
- The `_worker.js` shim is generated by `Guide/scripts/postbuild-pages.mjs` during `npm run build` — never skip the build step unless `dist/client/_worker.js` is confirmed present.

## D1 queries (WY_DB)

Run ad-hoc queries from `Guide/`:
```bash
npx wrangler d1 execute WY_DB --remote --command "SELECT COUNT(*) FROM guide_rubric_scores;"
```

Or from `Candidates/` (same binding, same database — either works):
```bash
cd Candidates
npx wrangler d1 execute WY_DB --remote --command "SELECT COUNT(*) FROM guide_rubric_scores;"
```
