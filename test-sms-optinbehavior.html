SMS Opt-In Behavior Test Plan

Testing the current SMS opt-in implementation in donateV1.js

Issue Analysis

The JavaScript code for SMS opt-in exists but has a critical flaw:

// Lines 233-249 in donateV1.js: Phone field listener if (phoneInput) { const handlePhoneCheck = () => { const isValid = isValidSmsPhone(phoneInput.value); if (isValid && smsConsentInput && !smsConsentInput.checked) { smsConsentInput.checked = true; // ← Sets property updateSmsConsentHint(true); // ← Updates UI // ✗ MISSING: smsConsentInput.dispatchEvent(new Event('change')) } if (smsConsentInput?.checked) { if (!isValid) { setFieldError(phoneInput, "Enter a valid mobile number..."); } else { setFieldError(phoneInput, ""); } } }; phoneInput.addEventListener("blur", handlePhoneCheck); phoneInput.addEventListener("change", handlePhoneCheck); }

PROBLEM: When phone is filled with valid number, the code sets checked = true but doesn't fire the 'change' event. This means the form doesn't know it changed.

Current Behavior vs Expected

Test 1: User fills phone with valid number

Expected:

  • SMS opt-in checkbox auto-checks
  • Hint "SMS opt-in requires a valid mobile number." appears
  • Phone field error (if any) clears

Actual:

  • ✓ Checkbox gets checked (checked property = true)
  • ✓ Hint shows (is-hidden class removed)
  • ✓ Phone error clears if valid
  • ✗ But 'change' event NOT fired on checkbox
  • ✗ So unchecking it later won't trigger the 'change' listener properly

Test 2: User checks SMS opt-in WITHOUT phone number

Expected:

  • Focus moves to phone field
  • Error: "Enter a valid mobile number for text opt-in." appears on phone
  • Checkbox remains unchecked (form prevents it)

Actual:

  • ✓ Focus moves to phone field
  • ✓ Error message shows
  • ✓ Checkbox doesn't stay checked

Test 3: User unchecks SMS opt-in

Expected:

  • Hint hides
  • Phone field errors clear
  • Form can be submitted without valid phone

Actual:

  • ✓ Hint hides (is-hidden added)
  • ✓ Phone error clears
  • ✓ Form can submit without phone

Root Cause

When smsConsentInput.checked = true is set programmatically (line 239), it does NOT fire the 'change' event.

This causes synchronization issues:

  1. Phone blur with valid number → checkbox.checked = true (but no event fired)
  2. User manually unchecks → 'change' listener fires → clears errors
  3. User checks again manually → 'change' fires → works fine
  4. But if phone field is filled and auto-checked, then manually unchecked, the state is now out of sync

The Fix

After setting smsConsentInput.checked = true, dispatch a 'change' event:

if (isValid && smsConsentInput && !smsConsentInput.checked) { smsConsentInput.checked = true; updateSmsConsentHint(true); // ADD THIS LINE: smsConsentInput.dispatchEvent(new Event('change', { bubbles: true })); }

This ensures that when the checkbox is auto-checked, the 'change' listener fires and all dependent logic runs.
